# Product trajectory from the validated local foundation

This document separates what is executable today from the path to a commercial
team product. Passing tests proves contract, privacy, and integration behavior;
it does not prove metric validity, production security, or customer value.

## Validated current foundation

| Area | What exists now | Honest boundary |
|---|---|---|
| All-20 metrics | One sealed twenty-state r5 publication, readiness v2-4, two-sentence guidance, full dashboard and compact overlay | 15 conditional measured paths; 0 task-profile gaps; 5 provider/extractor gaps; unknown is not a failure or zero |
| Local agent evidence | Historical v1/r4 and current v2/r5 canonical file contracts, preview/import, inert proposals, paged review UI, owned-window native decisions, fresh-snapshot publication | Covers five collaboration lifecycle families only; an agent cannot verify its own claim; standard serve/attached mode stays proposal-only |
| Local models | Three small factor experts, optional bounded Qwen adjudicator, immutable stage/resource receipts, hardware compatibility catalog | Eight experimental metric paths; uncalibrated, product-ineligible, and never measured authority |
| Task work | Evidence-honest proposal/revision/review/analysis timeline plus authoritative lifecycle ledger foundations | Analysis completion is not task completion; automatic backlog/in-progress/done inference remains forbidden without explicit lifecycle receipts |
| Team/control plane | Default-off development contracts, RBAC/policy attacks, readiness-only local UI, content-free sync envelope foundation | No production IdP, PostgreSQL/RLS adapter, durable remote transport, billing, or safe aggregate release |
| Social/direct files | Invite-only social and direct-file contracts, durable local metadata foundation, synthetic direct-transfer UI/prototype | No production identity, reviewed E2EE/key custody, authenticated signaling, internet reachability, TURN policy, or production byte transport |
| Paid deep analysis | Tenant, entitlement, spend, approval, job, webhook, and synthetic-provider contracts with a read-only readiness route | No real Stripe, OIDC, OpenAI/Anthropic adapter, provider key custody, remote listener, or paid command API |

## Product boundary

The offline local application remains useful without an account: local model
analysis, local history, export, deletion, and the loopback agent API must not be
held hostage by a subscription or network outage. Paid entitlement gates the
hosted developer API, team synchronization, managed retention, and explicitly
approved deep analysis. This matches the requested loginless local edition plus
account/team features after login.

The local loopback API uses an installation token. The future hosted API uses
tenant-bound, expiring, revocable, scoped clients after login and entitlement.
It never exposes raw SQL, local files, personal Codex/Claude CLI sessions, or an
ability for an LLM to mutate the application without the existing command and
approval boundaries.

## Ordered delivery trajectory

### 1. Close the five remaining non-model metric seams

1. **Delivered in r5:** a separate reviewed task-profile editor for constraints,
   acceptance outcomes, and deliverable slots. Owned-window native confirmation appends an
   immutable revision whose fingerprint is sealed into a fresh snapshot; it is
   not an agent-authored evidence file.
2. Add reviewed requirement/plan extraction for decomposition coverage, with
   explicit opportunity ownership and correction history.
3. Add objective proposal bundles for hypothesis, requirement-action, material
   claim, and requirement-verification families. The app issues opportunity
   identities; imported files may propose links and receipts but cannot invent
   success authority. Native confirmation and provider receipts are distinct.
4. Keep old projections readable and introduce a new append-only identity for
   every semantic change. Never reinterpret historical numbers.

Acceptance: every one of the twenty metrics has a tested path to
known/pending/not-applicable from legitimate synthetic evidence; absent or
unconfirmed evidence remains unknown; no agent/model self-verification.

### 2. Prove metric and model validity

Build representative, blinded EN/PL datasets per metric and per evidence family.
Measure precision/recall, calibration, selective risk, abstention, stability,
language/task/provider slices, latency, RAM/VRAM, and incremental value over the
deterministic baseline. Route each factor to the smallest reviewed expert panel
that adds calibrated value; do not optimize for model count. Keep Qwen/deep
judges selective and bounded.

Acceptance: promotion is per metric and model revision, with immutable holdout
and provenance receipts. A failed or missing model leaves the measured snapshot
intact. Product eligibility stays false until the reviewed gates pass.

### 3. Production identity, subscription, and hosted API

Deploy a separate HTTPS control-plane service backed by managed PostgreSQL with
tenant keys and RLS. Add OIDC/passwordless account recovery, device pairing,
scoped API clients, audit, rate limits, deletion/export, backups, and key
rotation. Add Stripe-hosted Checkout/Portal plus signed webhooks and an
append-only entitlement ledger. Local development can run the service on this
PC; production must not depend on this PC being online.

Acceptance: cross-tenant/IDOR, revocation, replay, webhook, deletion, backup,
and recovery attacks pass. Local offline use continues when identity, Stripe,
or the server is unavailable.

### 4. Paid deep-analysis judge gateway

Use official commercial OpenAI/Anthropic APIs with service credentials, never a
person's logged-in CLI. Each job requires entitlement, spend hold, exact
redaction preview, one-time disclosure approval, model/region/retention binding,
structured response validation, timeout/cancellation, and settlement. Multiple
judges return independent judgments and uncertainty; they never directly write
measured metrics. A deterministic adjudicator may turn reviewed judgments into
an experimental receipt only after calibration.

Acceptance: no provider call without approval and budget; payloads absent from
logs/audit; provider failure cannot erase local results; per-user/org caps and
retention/deletion workflows verified.

### 5. Team analytics and task collaboration

Sync only signed, allowlisted, content-free aggregate/snapshot envelopes first.
Ship Me by default; Team/Organization views require explicit field policy,
cohort suppression, overlap/differencing defense, and audited individual-access
grants. Add authoritative task lifecycle events, assignees, priorities,
dependencies, comments, and corrections before projecting Kanban or Jira-like
states.

Acceptance: tenant isolation, membership/device revocation, deletion
propagation, cursor/replay behavior, stable cohorts, query budgets, and exact
dashboard/overlay parity pass under production adapters.

### 6. Secure social chat and direct files

Add production identity-bound friend/channel membership, a reviewed E2EE
protocol/library and device key lifecycle, authenticated signaling, abuse/rate
controls, and deletion/export policy. Direct file bytes travel peer-to-peer only
after recipient consent and owner approval; the server may carry bounded
signaling metadata but not file bytes. Symmetric NAT/CGNAT failure is explicit
unless a separately approved TURN relay policy is introduced.

Acceptance: blocked users cannot enumerate or contact; device revocation races,
membership changes, replay, integrity, resume, expiry, quarantine, and no-recall
semantics pass. Offline send queues remain sender-local.

### 7. Supported Windows release

Produce a reproducible signed MSIX/AppInstaller pipeline with bundled runtime,
SBOM/provenance, private data ACLs, signed updates, staged rollout, rollback,
backup/restore tests, uninstall behavior, vulnerability reporting, and an
independent security review.

Acceptance: clean-machine install/update/rollback/uninstall and recovery tests
pass; the public manifest may then change from `distributable=false` only in a
separately reviewed release commit.

## Immediate next implementation

The next metric tranche is one provider/extractor gap end to end: reviewed
requirement/plan extraction for decomposition, or one objective family with
app-issued opportunity identities, explicit links, and typed outcome receipts.
It must retain the r5 profile binding, append a new projection identity for any
semantic change, and prove the full API/UI/readiness path before generalizing to
the other four gaps. No model-authored prose or pass claim may become measured
authority.
